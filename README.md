## موقع رحيق RAHEEQ — الصفحة الرئيسية للمشروع

**`index.html` هو أساس الموقع**: منصة عربية RTL كاملة لتسجيل ولي الأمر،
مبنية كموقع حقيقي بملفات منفصلة (وليس ملف HTML واحدًا):

```text
index.html              الصفحة الرئيسية (كل الأقسام)
css/raheeq.css          الهوية البصرية + الحركات + الاستجابة + منظومة الخطوط متعددة العائلات
css/intro.css           انيميشن البداية: أعمدة بيانية 3D + تجمّع شعار رحيق + الوميض
js/intro.js             مشغّل الانيميشن (غبار ذهبي، خط الترند، التخطي بـ Escape/زر)
js/sounds.js            محرك الأصوات (Web Audio + ملفات MP3) والاهتزاز
js/confetti.js          قصاصات النجاح ماروني + ذهبي
js/validation.js        قواعد التحقق من الحقول
js/uploads.js           قراءة الصور الفعلية وضغطها وحفظها + سجلات المستندات
js/api.js               إرسال الطلب والمستندات إلى خادم الرفع (/api/registrations)
js/app.js               الخطوات، الدخول، النجاح، LocalStorage، المزامنة
server/serve.py         خادم الموقع + واجهة الرفع (Python قياسي فقط)
server/api.py           التحقق والتخزين الآمن للطلبات والمستندات
sounds/*.mp3            الأصوات الثمانية (MP3 حقيقية)
assets/brand/*          الشعار والأيقونات
assets/fonts/*          خط Cairo محلي (احتياطي لـ Google Fonts)
raheeq.webmanifest      إعدادات التطبيق على الجوال
```

```bash
python3 server/serve.py --no-browser      # ثم افتح http://localhost:8000/
```

* `raheeq.html` صار **صفحة تحويل** إلى الجذر، وصفحة «مجلس الصوت» القديمة محفوظة
  في `majlis.html` (روابطها الداخلية محدّثة)، فلا ينكسر أي رابط قديم.
* **هيدر ثابت** باللوجو يمينًا وزر «تسجيل دخول ولي الأمر» يسارًا مع زر الصوت 🔊/🔇.
* **هيرو**: العنوان + وصف + 4 شارات + بطاقة التسجيل على اليسار.
* **3 خطوات مع مؤشر تقدم**: ولي الأمر ← الطالب ← المستندات، مع **رفع الصور الفعلية**:
  كل ملف يُقرأ بـ `FileReader` ثم تُضغط الصورة على `Canvas` (حتى 1400px، JPEG) وتُحفظ
  **بيانات الصورة نفسها** مع سجل الطلب في `raheeq_users`، لا اسم الملف فقط.
  شهادة الميلاد والصورة الشخصية إلزاميتان، وبيان النجاح اختياري.
  صور JPG/PNG/WEBP/GIF/BMP وملفات PDF فقط (حتى 700KB لـ PDF)؛ SVG وHTML مرفوضة.
  بعد الإرسال تظهر الصور في شاشة النجاح، وبعد تسجيل الدخول تظهر في «المستندات المرفوعة»
  مع أزرار **عرض بالحجم الكامل** (نافذة معاينة) و**تنزيل**.
* **بلا رقم قومي وبلا بطاقة ولي الأمر**: الخانتان أُزيلتا من كل صفحات الموقع
  (الاستمارة، تحقق العميل، رسالة واتساب، رفع الطلب على الخادم، وردود رحيق)،
  ولم يتغيّر ترتيب بقية الخانات ولا أي تفاصيل أخرى.
* **أزرار الاتصال والواتساب على اليمين** (`css/contact-bar.css`)، و**رحيق على الشمال**
  (`css/yaseen.css`)، فلا تتقاطع حركتها معها.
* **رحيق تتحرك بحرّية في أي مكان بالشاشة**: ولي الأمر يسحبها بالفأرة أو اللمس
  إلى أي نقطة (أعلى/أسفل/أركان)، أو يحرّكها بالأسهم، أو يختار مشي/ركض/قفز من لوحة
  الحركات؛ الموضع محفوظ داخل حدود الشاشة. وعند اكتشاف خطأ في خانة تنتقل رحيق فعلًا
  إلى **مكان الخطأ** في أي موضع بالصفحة، تتبع الخانة وهي متحركة، وتعود لمكانها بعد ذلك.
* **تحقق**: الموبايل 11 رقمًا، الإيميل يحتوي `@`،
  كلمة السر 6 أحرف ومتطابقة، الموافقة على الشروط — رسالة حمراء + اهتزاز خفيف عند الخطأ.
* **شاشة نجاح**: 🎓 تم استلام طلبك بنجاح + اسم ولي الأمر والطالب والصف +
  رقم الطلب `RHQ-1234` + «هنتواصل معاك خلال 24-48 ساعة» + قصاصات ماروني وذهبي.
* **صندوق دخول** و**4 بطاقات قيم** (ثقة، نمو، رعاية، تميز) وفوتر
  `© 2026 رحيق RAHEEQ - info@raheeq.edu`.
* **الحساب والمستندات يُحفظان في `LocalStorage`** (`raheeq_users`) ليتمكن ولي الأمر من
  الدخول لاحقًا من نفس الجهاز ورؤية صوره بعد إغلاق الصفحة. بعد الحفظ يفتح ولي الأمر
  واتساب أكاديمية رحيق (`201151947735`) برسالة جاهزة بكل بيانات الطلب، ويرفق صور المستندات
  من داخل المحادثة (أو عبر زر المشاركة على المتصفحات الداعمة). التخزين محدود (~5MB)؛
  عند امتلائه يقلّل الموقع جودة الصور تلقائيًا، وإن لم يكفِ يطلب صورة أصغر.
  ولي الأمر مسؤول عن سرية كلمة السر الخاصة بحسابه.
* **الأصوات**: الملفات الثمانية من `sounds/` تُحمّل مسبقًا عند فتح الصفحة،
  وتُشغّل عند التفاعل فقط (متوافقة مع الجوال). راجع `sounds/README.md`.

## واجهة الرفع (API)

بعد حفظ الطلب، المسار الأساسي هو **إرسال الطلب إلى واتساب أكاديمية رحيق** بضغطة واحدة
(رسالة جاهزة + إرفاق الصور). وإذا كان خادم الأكاديمية مُشغَّلًا، ترسل الواجهة الطلب إليه
تلقائيًا أيضًا عبر `js/api.js` (مع إعادة محاولة يدوية إن فشل الاتصال)، وتحتفظ بنسخة دائمًا.

```bash
# تشغيل الموقع + الواجهة على نفس المنفذ
python3 server/serve.py --no-browser

# لتفعيل قراءة الطلبات والمستندات (إدارة الأكاديمية)
RAHEEQ_ADMIN_TOKEN="رمز-قوي-خاص" python3 server/serve.py --no-browser

# مجلد تخزين مختلف (افتراضي: data/)
RAHEEQ_DATA_DIR=/var/lib/raheeq python3 server/serve.py
```

| المسار | الوصف | المصادقة |
| --- | --- | --- |
| `GET /api/health` | حالة الواجهة وقدراتها (بلا بيانات شخصية) | عام |
| `POST /api/registrations` | رفع طلب تسجيل مع صور المستندات (JSON + base64) | عام (بحدّ معدل) |
| `GET /api/registrations` | قائمة الطلبات | `X-Admin-Token` |
| `GET /api/registrations/<رقم>` | تفاصيل طلب (بدون كلمة السر) | `X-Admin-Token` |
| `GET /api/registrations/<رقم>/<مستند>` | ملف المستند نفسه | `X-Admin-Token` |

مثال رفع (نفس ما ترسله الواجهة):

```bash
curl -s http://localhost:8000/api/registrations \
  -H 'Content-Type: application/json' \
  -d '{
    "parentName": "محمد أحمد علي حسن",
    "nationalId": "12345678901234",
    "mobile": "01000000000",
    "email": "waly@raheeq.edu",
    "password": "secret1",
    "studentName": "عمر محمد أحمد علي",
    "dob": "2015-05-10",
    "grade": "KG1",
    "address": "القاهرة مدينة نصر",
    "docs": {
      "birthCert": {"name": "birth.jpg", "dataUrl": "data:image/jpeg;base64,..."},
      "photo": {"name": "photo.jpg", "dataUrl": "data:image/jpeg;base64,..."},
      "parentCard": {"name": "card.jpg", "dataUrl": "data:image/jpeg;base64,..."}
    }
  }'

# إعادة قراءة المستندات لاحقًا (إدارة)
curl -s -H 'X-Admin-Token: رمز-قوي-خاص' http://localhost:8000/api/registrations
curl -s -H 'X-Admin-Token: رمز-قوي-خاص' \
  http://localhost:8000/api/registrations/RHQ-1234/photo --output photo.jpg
```

**التخزين والأمان:**

```text
data/                                 (مستثنى من Git — بيانات شخصية)
├── registrations/<رقم الطلب>.json    بيانات الطلب + أوصاف المستندات (بلا base64)
├── registrations/index.json          فهرس مختصر للطلبات
└── uploads/<رقم الطلب>/<المستند>.*   صور المستندات الفعلية (صلاحيات 600)
```

* الصور تُفحص بالبصمة الحقيقية للبايتات (Magic Bytes) لا بالامتداد: JPG/PNG/WEBP/GIF/PDF فقط،
  وSVG/HTML مرفوضة، بحد 4MB للمستند و7MB للطلب.
* كلمة السر تُخزَّن مشفّرة `PBKDF2-SHA256` (120 ألف دورة + ملح عشوائي)، ولا تُعاد أبدًا في أي رد.
* مجلد `data/` و`/server/` و`/.git/` غير قابلة للوصول عبر الموقع، وقراءة الطلبات تتطلب رمز إدارة.
* حدّ معدل 10 طلبات رفع في الدقيقة لكل عنوان IP، وأحجام الطلبات محدودة قبل قراءتها.
* عند إيقاف الخادم أو تعطّله يظل التسجيل يعمل بحفظ محلي كامل (بدون فقدان الصور).

الاختبارات: `node tests/node/raheeq-tests.mjs` (بنية الموقع + المنطق + تدفق رفع الصور وحفظها في `LocalStorage` واستعراضها + الواجهة)،
`python3 tests/python/test_api.py` (26 اختبارًا للخادم: التحقق، البصمة، التخزين، الصلاحيات، حد المعدل)،
`node tests/node/dom-smoke.mjs` (واجهة الاستوديو، يحتاج `jsdom`).

### انيميشن البداية (Intro) — `index.html` فقط

كل مرة تُفتح فيها الصفحة الرئيسية يعمل مشهد افتتاحي سينمائي (~4.6 ثانية)،
ويمكن تخطيه بزر «تخطي» أو بمفتاح `Escape`:

1. **مسرح برغندي**: أرضية بشبكة منظورية ذهبية تتلاشى وشعاع علوي و«غبار» ذهبي عائم.
2. **درجات بيانية 3D**: سبعة أعمدة ثلاثية الأبعاد (وجه أمامي مموّج + وجه علوي ذهبي مضاء + وجه جانبي) تتصاعد كالمدرجات من الطرفين نحو **قمة واحدة في المنتصف**، مع **خط ترند ذهبي** يلمع ويربط قمم الأعمدة (يُقاس ويضبط عبر JS في `js/intro.js`).
3. **الشعار يتفكك ويتجمع**: الشعار الرسمي (`raheeq-mark-vector-white.svg`) يصل إلى **13 شظية** مقصوصة بـ `clip-path` تنطلق من عمق الفراغ (translate3d + rotate3d + blur) وتلتحم واحدة واحدة في منتصف الشاشة **فوق أعلى درجة بيانية**.
4. **الظهور دفعة واحدة**: لحظة التحام آخر شظية ينفجر **وميض** شعاعي + موجة ذهبية دائرية + اشتعال القمة، ثم تظهر قفلة «رحيق» (أميري بتدرج ذهبي) فوق «RAHEEQ» (Cinzel بتباعد حروف)، فالفاصل الذهبي ✦ والسطر «أكاديمية رحيق · بوابة ولي الأمر» (ريم كوفي).
5. شريط تقدّم ذهبي سفلي، وبعدها يزول الغطاء من الـ DOM وتظهر الصفحة.

ملاحظات تنفيذية:

* **CSS 3D خالص + SVG + JS قياسي** — بلا أي مكتبات خارجية (3D حقيقي عبر `perspective`/`transform-style:preserve-3d`).
* أثناء العرض يُقفل التمرير (`body.raheeq-intro-lock`)، وبعده تُزال القفلة ويُزال الغطاء من الـ DOM.
* **`prefers-reduced-motion`** يحترم: يُلغي المشهد ويظهر الشعار فورًا. لو تعذّر الـ JS تمامًا، يُخفي الغطاء نفسه تلقائيًا بعد مهلة (`introFailsafe`) ولا يحبس الصفحة.
* الشظايا مُنفَّخة ~3.5% حول مراكزها لمنع الشقوق الضوئية بين القطع، والتغطية الكاملة مُتحقَّق منها بفحص شبكي (40 ألف نقطة).
* يظهر في **كل** تحميل للصفحة (قرار تصميمي)، ويُعيد الرسم في كل زيارة.

### القائمتان في خطوة «الطالب» (`index.html`)

* قائمة **نوع البرنامج** (`#programType`): «تأسيس» أو «منهج دراسي» (إلزامي).
* **لو تأسيس** (`#foundationBranch`): قائمة مستوى التأسيس (`#foundationLevel`: للصغار/للكبار)
  + **قائمة مواد التأسيس** (`input[name="foundationSubjects"]` — مادة أو أكثر إلزامية من
  القائمة البيضاء: العربية، الإنجليزية، الرياضيات، القراءة والكتابة).
* **لو منهج دراسي** (`#curriculumBranch`): قائمة **السنة الدراسية** (`#grade`) —
  KG1/KG2 وكل الصفوف حتى «3 ثانوي» فقط، ويُكمل التسجيل مباشرة.
* التحقق في `js/validation.js` (`step2`) حسب نوع البرنامج، والبيانات تُحفظ وتُعرض
  وتُرسل لواتساب والخادم حسب الاختيار (`programType` + `grade` أو `foundationLevel` + `foundationSubjects`).

أصلحت في `2026-11-15` مجموعة أسباب كانت تمنع ولي الأمر من الانتقال للخطوة التالية:

* **الخانة التي لا تُكتب أبدًا:** كان `js/app.js` يقطع كل الحقول الرقمية عند 11 رقمًا
  (`slice(0, 11)`) بينما التحقق يشترط 14 للرقم القومي — فالحقل كان مستحيلًا.
  الآن الأطوال في مصدر واحد: `NATIONAL_ID_LEN` و`MOBILE_LEN` في `js/validation.js`
  يستهلكهما `js/app.js` (لا يمكن أن يختلفا مرة أخرى).
* **السبب الحقيقي مخفي:** واجهة الخطأ كانت تُظهر *أول* خطأ فقط، فتُخفي سبب التعطّل
  وتعرض رسالة قديمة لا علاقة لها بما يُعيق المستخدم. الآن `buildErrorText()` تعرض
  **كل** الأخطاء الحالية، وترجع رسالة الإرسال إلى الخطوة التي فيها الخطأ.
* **وضوح المطلوب أثناء الكتابة:** عدّاد مباشر في خانة الاسم («2 من 4 أجزاء») وفي
  خانة الموبايل («7/11») وترجمته مع بقية الواجهة (`data-counter`).
* **رسائل أوضح:** خطأ الاسم يوضّح الأجزاء الأربعة المتوقعة، وخطأ الموبايل يذكّر
  أنه يبدأ بـ `01`.
* **تغيير اللغة يحدّث كل شيء:** حدث `raheeq:langchange` كان يُنشر على `window` فقط
  بينما المستمعون على `document` — فلم تتحدّث رسائل التحقق ولا العدّادات.
  صار يُنشر على الاثنين (`js/settings.js`).

### سياسة الكاش وبصمة الإصدار (لماذا كانت التحديثات لا تصل المستخدمين)

* `vercel.json` كان يخدم `js/*.js` و`css/*.css` بـ `Cache-Control: max-age=31536000, immutable`
  على أسماء ملفات **بلا بصمة إصدار** — أي أن المتصفح يحتفظ بها سنة كاملة ولا يجرّب
  النسخة الجديدة. النتيجة: HTML قديم + JS جديد (أو العكس) = استمارة معطوبة.
* الآن: `js`/`css` تُعاد التحقق دائمًا (`max-age=0, s-maxage=86400, stale-while-revalidate`)،
  و`assets`/الصور/الأصوات تبقى `immutable` (سنة — فهي ثابتة)، وصفحات HTML تُقدَّم
  بـ `must-revalidate` فلا تُخدم نسخة قديمة أبدًا.
* وكل روابط `js/` و`css/` في صفحات الموقع تحمل **بصمة إصدار** (`?v=20261115-1`)
  تُحدَّث مع كل نشر.
* نفس السياسة مطبَّقة في `server/serve.py` (الخادم المحلي).
* `sw.js` (Service Worker) لم يعد يخزّن `index.html` وسكربتات النموذج مسبقًا،
  وصفحات التنقّل تُجلب بـ `cache: 'no-store'`.

### أمان الموقع (Hacker pass)

* لا XSS مخزّن: `cart.html`/`shop.html`/`product.html`/`products.js` يهربون كل interpolations
  قبل `innerHTML` (`escHtml` في `script.js`)، والسلة تُطهَّر عند القراءة من `localStorage`.
* كلمات السر لا تُخزن نصًا أبدًا: `js/crypto.js` يحسب `sha256$salt$hash` (Web Crypto مع
  بديل JS خالص)، و`LocalStorage`/Xادم يستقبلان hash فقط (`api.py` يخزن PBKDF2 فوقه).
* `server/serve.py` يرسل لكل استجابة: `X-Content-Type-Options: nosniff`، `X-Frame-Options: DENY`،
  `Referrer-Policy: no-referrer`، و`Content-Security-Policy` (مع `object-src 'none'` و`base-uri 'self'`)،
  ويحجب كملفات ثابتة: `data/` و`server/` و`tests/` و`api/_yaseen/` وكل dotfiles و`package.json`.
* `vercel.json` يضيف نفس الرؤوس لكل المسارات على Vercel + redirects لـ dotfiles.

## رحيق YASEEN — المساعد الذكي (ذكاء اصطناعي حقيقي يجاوب أي سؤال)

شخصية تفاعلية تظهر في صفحات الموقع (`index.html` وغيرها). **رحيق ذكاء اصطناعي كامل (xAI Grok أو Groq) يرد على أي سؤال** — داخل
محتوى الموقع (التسجيل، الأكاديمية، الخانات وأخطائها) وخارجه (رياضة، علوم، كتابة، ترجمة، برمجة، أي موضوع) — وليست
بوتًا بإجابات محفوظة. الأزرار السريعة ومحرك القواعد بقيا **احتياطيًا**: يظهر عند غياب مفتاح الذكاء الاصطناعي أو فشله، أو
للأسئلة الشائعة والتنقل في الاستمارة. مفتاح الإيقاف الفوري من لوحة المدير يوقفها كاملة.

| الجزء | الملف | أين يعمل |
| --- | --- | --- |
| الحدود + محرك الردود الاحتياطي (القواعد) | `api/_yaseen/yaseen-system.js` | الخادم فقط |
| التخزين المشفّر (AES-256-GCM) | `api/_yaseen/store.js` → `data/yaseen/store.enc` | الخادم فقط |
| دخول المدير (bcrypt + OTP) | `api/_yaseen/auth.js` | الخادم فقط |
| المسارات | `api/_yaseen/handler.js` (+ `api/yaseen.js` لـ Vercel، `server/yaseen-server.js` محليًا) | الخادم فقط |
| طبقة الذكاء الاصطناعي (Grok / Groq) — اختيارية، بلا مفتاح = محرك القواعد | `api/_yaseen/ai.js` (البرومبت والتحقق) + `api/_yaseen/providers.js` (المفاتيح والموديلات والاتصال والتشخيص) + `api/_yaseen/site-knowledge.js` (معرفة الموقع والخانات) | الخادم فقط |
| الشكل والحركة ونافذة المحادثة | `js/yaseen.js` (+ `BASE`: الشكل الأساسي قبل رد الخادم) + `css/yaseen.css` + `assets/yaseen/` | المتصفح (عرض فقط) |
| لوحة المدير المخفية | `/admin-yaseen/` (غير مرتبطة من أي صفحة) | المتصفح + فحص على الخادم |

**كيف تُحسم الرسائل على الخادم بالترتيب:** الحدود والحظر الصارم يعملان **قبل** أي ذكاء اصطناعي، ومخرجات
النموذج تتحقق بالكامل قبل وصولها للمتصفح. الترتيب على الخادم:

1. حدود: 400 حرف للرسالة، 20 رسالة للجلسة، حد لكل عنوان IP، وCAPTCHA حسابية عند الإرسال السريع.
2. الروابط والملفات مرفوضة (المحادثة تقبل JSON نصيًا فقط).
3. كلمات المدير المحظورة ⟵ رد ثابت برفض مهذب — ولا يُستدعى النموذج.
4. لو مفتاح Grok (`XAI_API_KEY`) أو Groq (`GROQ_API_KEY`) مضبوط على الخادم: **النموذج** يجاوب **على أي سؤال** — من «معرفة الموقع» (`site-knowledge.js`)
   لحقائق الأكاديمية والتسجيل، ومن معرفته العامة لأي موضوع آخر — مع تفاصيل الخانات المتعثرة من الاستمارة
   (أسماء فقط — بلا قيم) وسجل آخر ٨ أدوار من المحادثة (ممحى منه الأرقام الطويلة والإيميلات). محاولات
   التلاعب («انسى تعليماتك»…) تصل للنموذج ويتعامل معها «رحيق الذكي» بشكل طبيعي زي أي مساعد ذكي حقيقي.
   الرد يُتحقق كاملًا: نص ≤ 900 حرف ممحى منه الروابط، تعبير من القائمة المعتمدة، خانة إشارة من القائمة
   البيضاء (وإلا تُلغى)، وأي فشل (شبكة/مهلة/مخرجات تالفة) ⟵ **رجوع تلقائي لمحرك القواعد**.
   لو المفتاح غير مضبوط: محرك القواعد — يجاوب أسئلة التسجيل المعتمدة، وأي سؤال خارجها يرد باعتذار
   مهذب («المساعد الذكي مش متاح دلوقتي…») مع بقائه متاحًا لأسئلة التسجيل.

المتصفح يستلم من `GET /api/yaseen-config` النصوص النهائية للعرض فقط (الترحيب، إرشاد الخانات، أسماء الأزرار)،
ولا يستلم القواعد أو الكلمات المفتاحية أو قائمة الإجابات.

**الشكل الأساسي دايمًا ظاهر:** رحيق تُبنى مع أول رسم للصفحة من نسخة أساسية محلية
(`BASE` داخل `js/yaseen.js`: الاسم + الترحيب + نصوص الإرشاد + الأزرار الأربعة — نفس نصوص الخادم
الافتراضية بلا أي قواعد أو كلمات مفتاحية). أول ما يرد `/api/yaseen-config` تُستبدل كل القيم بإعداد
المدير. بالتالي لا تختفي الشخصية لو تأخّر الخادم أو الطلب الأول فشل (شبكة بطيئة، حجب، بدء بارد،
استضافة ثابتة) — وهو ما كان يجعلها تبدو كأنها مُزالة. تختفي رحيق في حالة واحدة فقط: أن يقول الخادم
صراحةً إن المدير أوقفها (kill switch). ولو تعذّر الوصول للخادم فالمحادثة توضّح ذلك وترشد ولي الأمر
إلى واتساب الأكاديمية برقمه الرسمي من `meta[name="raheeq-whatsapp"]`. انحراف النصوص بين النسختين
ممنوع باختبار يطابق `BASE` مع `system.publicConfig(system.defaultConfig())`.

### الذكاء الاصطناعي (xAI Grok / Groq) — رحيق بتفهم وتشرح بالتفصيل

رحيق ذكاء اصطناعي كامل بكل معنى الكلمة: لما ولي الأمر يسأل **أي** سؤال — عن خطأ في خانة، أو عن أكاديمية
رحيق، أو أي موضوع عام تمامًا (رياضة، علوم، كتابة رسالة، ترجمة، برمجة…) — بيرد النموذج بإجابة مفصلة
وبالعامية المصرية:

* **أي خانة متخبط فيها**: الموقع يبعت للنموذج **أسماء** الخانات المتعثرة فقط (لا قيمها) + رقم الخطوة،
  وهو يشرح كل خانة: يعني إيه المطلوب + ليه بيرفض + الحل خطوات مرتبة + مثال لقيمة صحيحة
  (مثال: الموبايل 11 رقم بالإنجليزي يبدأ بـ `01`، الاسم الرباعي ٤ أجزاء بالمسافات، الإيميل فيه `@`،
  كلمة السر ٦ أحرف+ وتتطابق في التأكيد، العنوان ٥ أحرف+...).
* **الموقع بيعمل إيه**: النموذج يعرف رحلة التسجيل كاملة — الخطوات الثلاث، المستندات (شهادة الميلاد والصورة
  الشخصية إجباري، بيان النجاح اختياري، PDF ≤ 700 كيلوبايت، الملف ≤ 12 ميجابايت، JPG/PNG/WEBP/GIF/BMP/PDF،
  ممنوع SVG وHTML)، الموافقة على الشروط، رقم الطلب `RHQ-xxxx`، المتابعة على واتساب الأكاديمية، الدخول من
  زر «تسجيل دخول ولي الأمر» في الهيدر، إن **مفيش رقم قومي** في الاستمارة إطلاقًا، وإن نسيان كلمة السر
  يتم عبر موظف الواتساب. ولما يُسأل عن حاجة مش في المعرفة (مصاريف/مواعيد/فروع) بيقول إنها مش مكتوبة
  ويحوّله لواتساب الأكاديمية بزر.
* **النطاق مفتوح**: النموذج يرد على أي سؤال بلا رفض مسبق؛ القيود الباقية هي: المحظورات التي يضبطها
  المدير، حظر الروابط، والحدود والجلسات — والمخرجات تتنظف (بلا روابط) وتُقصّ وتتحقق قبل المتصفح.
* **الخصوصية**: القيم (موبايل/باسورد/اسم/تاريخ ميلاد/عنوان) **لا تُرسل** للنموذج أبدًا — نرسل نص السؤال
  + أسماء الخانات المتعثرة بس. وأي أرقام طويلة (٦+ بما فيها العربية) أو إيميل تتكتب في السؤال عن طريق الخطأ
  تُستبدل `⟨رقم مخفي⟩` / `⟨بريد مخفي⟩` قبل الإرسال وقبل التخزين في سجل الجلسة.
* **الموديلات**: Grok ⟵ `grok-4.3` (بلا تفكير = أسرع وأرخص) ثم `grok-4.20-0309-non-reasoning` ثم `grok-4.7`؛
  Groq ⟵ `openai/gpt-oss-120b` ثم `openai/gpt-oss-20b` ثم `qwen/qwen3.8-27b` — بدرجة حرارة 0.7 وJSON mode.
* **الإطفاء الكامل**: `GROQ_AI=0` أو حذف المفتاح — رحيق تفضل شغالة بمحرك القواعد كما هو.

تشغيل محليًا (المتغير يتنقل تلقائيًا من `serve.py` إلى خادم Node):

```bash
XAI_API_KEY="xai-..." python3 server/serve.py --no-browser     # Grok
GROQ_API_KEY="gsk_..." python3 server/serve.py --no-browser    # أو Groq
```

**ربط المفتاح على Vercel (خطوة بخطوة):**

1. اعمل مفتاح من [console.x.ai](https://console.x.ai) ← API Keys (يبدأ بـ `xai-`)، أو من
   [console.groq.com/keys](https://console.groq.com/keys) (يبدأ بـ `gsk_`). مفتاح xAI يحتاج رصيد في الحساب.
2. Vercel ← المشروع ← **Settings → Environment Variables** ← أضف `XAI_API_KEY` (أو `GROQ_API_KEY`) والقيمة هي
   المفتاح فقط (بلا مسافات أو علامات تنصيص)، وفعّل Production وPreview.
3. **Deployments ← آخر نشر ← Redeploy** — المتغيرات لا تُطبَّق على النشر القديم.
4. افتح **`/api/yaseen-ai-status`** على الموقع: يقول بالعربي هل المفتاح موجود، ومقبول، وفيه رصيد، وأي موديل
   رد فعلًا (`"working": true`) — أو سبب الفشل بالظبط (مفتاح مرفوض / لا رصيد / ضغط مؤقت…) بدون كشف أي جزء من المفتاح.

**أي اسم متغير يشتغل:** الكود يقرأ `XAI_API_KEY` و`GROK_API_KEY` و`GROQ_API_KEY` و`AI_API_KEY` و`API_KEY`… بل وأي
متغير قيمته مفتاح يبدأ بـ `xai-` أو `gsk_`، ويكتشف المزود من بداية المفتاح (مفتاح `xai-` يروح لـ xAI حتى لو اسمه
`GROQ_API_KEY`). أكثر من مفتاح مفصولين بفاصلة = تبديل تلقائي لو مفتاح اترفض أو خلص رصيده.

**الموديلات لا تتعطل بالتقاعد:** الموديلات القديمة (`grok-2-latest`، `grok-beta`، `llama-3.3-70b-versatile`،
`llama-3.1-8b-instant`…) اتشالت من xAI وGroq في 2026 وكانت سبب إن الذكاء الاصطناعي بطّل يرد. الكود دلوقتي يجرّب الموديلات
الحالية، ولو `GROQ_MODEL`/`GROK_MODEL` مضبوط على موديل متقاعد أو موديل مزود تاني يتجاهله، ولو موديل رد «غير موجود»
يسأل المزود عن الموديلات المتاحة للمفتاح (`GET /v1/models`) ويختار أنسبها تلقائيًا. لو المزود رفض معاملًا معينًا
(مثل `reasoning_effort` أو JSON mode) يعيد الطلب من غيره بس. وكل محاولات الرد محكومة بمهلة إجمالية 16 ثانية
(`AI_BUDGET_MS`) أقل من مهلة المتصفح، و`vercel.json` يعطي الدالة 30 ثانية.

اختياريًا: `GROK_MODEL` / `GROQ_MODEL` لفرض موديل، `GROQ_TIMEOUT_MS` (مهلة المحاولة الواحدة، افتراضي `12000`)،
و`GROQ_AI=0` لإطفاء الاصطناعي دون حذف المفتاح. بدون أي مفتاح: القواعد كما كانت بلا تغيير.
لوحة المدير (قسم «القواعد المقفولة») تعرض المزود والموديل واسم متغير المفتاح ونتيجة آخر محاولة، و
`GET /api/yaseen-admin/aistatus` يعرض التشخيص مع رسالة خطأ المزود كاملة. سجلات Vercel (Logs) تكتب سبب أي فشل
(`[yaseen] AI failed … auth xai-grok/grok-4.3 http 400 …`) بلا المفتاح.

### قنوات الأكاديمية وحركة رحيق

* روابط يوتيوب وفيسبوك وإنستجرام وتيك توك الأصلية محفوظة كما هي، وتظهر الآن في فوتر الرئيسية تحت «تابع أكاديمية رحيق»، مع رابط «قنواتنا» في الهيدر وواتساب الأكاديمية. الروابط HTML مباشرة ولا تحتاج JavaScript.
* شخصية رحيق بشكلها الأصلي ثنائي الأبعاد (صور `assets/yaseen/*.webp` بإطاراتها الثمانية) — بلا WebGL ولا محركات خارجية. فوق الشكل طبقة حركات كثيرة بأنماط CSS: مشي وركض بانتقال فعلي عبر الشاشة مع تغيير اتجاه الوجه، قفز، رقص، دوران، شقلبة، نطّة، أرجحة، تمدد، طفو، دوخة، إيماءة «أيوة» وهزّ رأس «لا»، إضافة إلى تعابير الصور نفسها (تلويح، إشارة، تفكير، قلق، احتفال) — ١٩ حركة في لوحة «حركات رحيق».
* عجلة حركات تلقائية تُشغّل حركة متنوعة كل فترة طالما ولي الأمر هادئ، وتتوقف أثناء المحادثة أو استخدام الاستمارة. يوجد زر إيقاف دائم للحركة، ويُحترم `prefers-reduced-motion`، ويمكن سحب الشخصية أو إعادتها لمكانها.
* الحركات إعدادات عرض فقط في لوحة المدير، ولا تغيّر قواعد الردود. مفتاح إيقاف البوت يزيل الحركات مع الشخصية.
* الكود في `js/yaseen-motion.js` والتنسيق في `css/yaseen-motion.css`.

```bash
npm run test:yaseen:motion   #اختبارات الروابط والحركات دون متصفح
npm test                    #كل اختبارات الموقع والخادم
```

### التشغيل

```bash
npm install                                  # مرة واحدة (bcryptjs لتشفير كلمة سر المدير)
node server/yaseen-admin-setup.js --email admin@example.com --name "مدير رحيق"
python3 server/serve.py --no-browser         # يشغّل خادم رحيق تلقائيًا (يتطلب Node 18+)
python3 server/serve.py --no-browser --preview  # نفس الشيء + السماح بتضمين الصفحة داخل إطار معاينة
```

أمر الإعداد يسأل عن كلمة السر (12 حرفًا على الأقل) ويطبع **سر تطبيق المصادقة** (Google Authenticator / Authy)
الذي يولّد رمز OTP. بعدها افتح `/admin-yaseen/` وادخل بالبريد + كلمة السر + الرمز.
خلف وكيل عكسي أضف `--trust-proxy` ليُحسب حد الرسائل لكل زائر لا للوكيل.

### لوحة المدير

الشخصية (الاسم والترحيب) · الإجابات والأزرار السريعة · إرشاد الخانات والخطوات · الحركات · الأصوات ·
مواعيد العمل · الكلمات المحظورة · **مفتاح الإيقاف الفوري** · تجربة رد · **سجل** بكل تغيير (المدير + الوقت + القيمة القديمة + الجديدة).
القواعد المقفولة (الحدود والردود الاحتياطية وأنماط كشف التلاعب) لا تتغير من اللوحة — فقط بتعديل `yaseen-system.js` ونشره.

### النشر على Vercel

`vercel.json` يوجّه `/api/yaseen-*` (ومنها `/api/yaseen-ai-status`) إلى الدالة `api/yaseen.js` بمهلة 30 ثانية. نظام ملفات Vercel للقراءة فقط، لذلك:

* ولّد القيم بـ `node server/yaseen-admin-setup.js --email ... --env` وأضفها في Environment Variables:
  `YASEEN_SECRET`، `YASEEN_ADMIN_EMAIL`، `YASEEN_ADMIN_NAME`، `YASEEN_ADMIN_PASSWORD_HASH`، `YASEEN_ADMIN_TOTP_SECRET`.
* **لتفعيل الذكاء الاصطناعي أضف `XAI_API_KEY`** (مفتاح Grok بصيغة `xai-...`) **أو `GROQ_API_KEY`** (مفتاح Groq بصيغة `gsk_...`) ثم Redeploy وتأكد من `/api/yaseen-ai-status` — اختياري؛ بدونه تعمل رحيق بمحرك القواعد (أسئلة التسجيل فقط وأي سؤال آخر يرد باعتذار مهذب).
* اربط قاعدة **Upstash Redis / Vercel KV** بالمشروع (`KV_REST_API_URL` و`KV_REST_API_TOKEN`) ليُحفظ ما يعدّله المدير
  وتعمل حدود الرسائل عبر كل النسخ. بدونها تعمل رحيق بالإعدادات الافتراضية، واللوحة للقراءة فقط،
  والإيقاف يكون بالمتغير `YASEEN_ENABLED=0`.

> مسار Vercel/KV مكتوب ومغطى باختبارات الوحدة لكنه لم يُجرَّب على نشر حقيقي بعد — جرّبه على Preview أولًا.

### حدود معروفة

* إخفاء «Inspect» في المتصفح غير ممكن فعليًا؛ الحماية الحقيقية أن القواعد والإعدادات ليست في المتصفح أصلًا.
  (قائمة الزر الأيمن معطّلة على الشخصية فقط كإجراء شكلي.)
* الـ CAPTCHA حسابية بسيطة؛ لحماية أقوى ضد البرامج الآلية اربط Cloudflare Turnstile أو hCaptcha.
* الصور السبع للتعابير مولَّدة من الصورة الأصلية (`assets/yaseen/src/`، وتُقصّ بـ `make_sprites.py`).

الاختبارات: `node tests/node/yaseen-tests.mjs` (منطق الخادم) و`node tests/node/yaseen-ai-tests.mjs`
(طبقة الذكاء الاصطناعي بمحاكاة كاملة بدون إنترنت: التفعيل/البرومبت/التحقق/الرجوع للقواعد) و
`node tests/node/yaseen-providers-tests.mjs` (محاكاة واقعية لـ xAI وGroq: الموديلات المتقاعدة، الاكتشاف التلقائي،
المفتاح المرفوض/بلا رصيد، المهلة الإجمالية، التشخيص الآمن) و`node tests/node/yaseen-widget-tests.mjs`
(ظهور الشخصية بلا خادم، احترام مفتاح الإيقاف، استبدال إعداد المدير، تطابق `BASE` مع الخادم).

### تشغيل مساعد رحيق الصوتي والذكاء الاصطناعي

1. على Vercel: **Settings → Environment Variables**، أضف `GROQ_API_KEY` لمفتاح Groq، أو `XAI_API_KEY` لمفتاح Grok، أو `OPENAI_API_KEY` لمفتاح OpenAI. اختر بيئة النشر المطلوبة وأعِد النشر. محليًا استخدم `.env` غير المتتبَّع مع `python3 server/serve.py`. لا تضع المفتاح في ملفات JS أو APK.
2. افتح `/api/yaseen-ai-status` على نفس الموقع وتأكد أن `working: true`. عنوان المحادثة يوضح إن كان المفتاح مُعدًّا، لكن وسم «رد بالذكاء الاصطناعي» لا يظهر إلا لرد ناجح من النموذج. إذا لم تضف مفتاحًا، يبقى إرشاد التسجيل بالقواعد.
3. افتح `/voice.html` أو اضغط شخصية رحيق في الموقع. اضغط المايك واسمح باستخدامه، راجع النص ثم اضغط «إرسال». يُقرأ الرد تلقائيًا بعد الإملاء إذا كان صوت عربي متاحًا وغير مكتوم. زر «اسمع الرد» يتيح القراءة يدويًا.

الموقع يحتاج HTTPS ومتصفحًا بخدمة إملاء (مثل Chrome حسب الجهاز). التطبيق يستخدم خدمة أندرويد للتعرّف على الكلام ومحرك تحويل النص إلى كلام؛ حدّث Android System WebView وثبّت حزمة صوت عربية عند الحاجة. قد تستخدم خدمة الإملاء مزوّدها عبر الإنترنت؛ الموقع وخادم المحادثة لا يستقبلان تسجيلًا من المايك، بل النص بعد الإرسال فقط. يمكن الكتابة إذا لم يتوفر الإملاء أو رُفض الإذن.

## مجلس الصوت — واجهة بسيطة + تطبيق APK للهاتف

مجلس الصوت يشغّل الصوت على **عدة سماعات في الوقت نفسه**. صار الآن سهلًا:
واجهة من ثلاث خطوات في المتصفح، وتطبيق **APK أصلي** للهاتف يفعلها فعلًا.

### تحميل التطبيق على الهاتف (APK)

1. افتح [مجلس الصوت](https://mistekawe.vercel.app/majlis.html) على أندرويد 6 فأحدث واضغط **تحميل تطبيق APK لأندرويد**. الرابط ينزّل ملف `majlis-debug.apk` مباشرة، وليس أرشيف الشفرة من GitHub.
2. افتح الملف بعد تنزيله، واسمح لمتصفحك أو مدير الملفات بالتثبيت من هذا المصدر إذا طلب أندرويد. إذا كانت هناك نسخة أقدم موقّعة بمفتاح اختبار مختلف، احفظ ما تحتاجه ثم احذفها وثبّت الجديدة؛ إلغاء التثبيت يمسح إعدادات التطبيق. لا تشارك ملف APK من مصدر غير موثوق.
3. داخل التطبيق اضغط **افتح مساعد رحيق الصوتي**. عند أول ضغطة للمايك يطلب أندرويد إذن الميكروفون؛ لو رفضته تقدر تكتب سؤالك أو تفعّله من إعدادات التطبيق. إذنا ملفات الصوت والأجهزة القريبة منفصلان عن المايك.

تعدد مخارج Bluetooth يعتمد على دعم الهاتف؛ `setPreferredDevice` يطلب توجيه المسار ولا يجبر النظام على ذلك. للمشغّل دعم تشغيل في الخلفية، أما المايك فيعمل فقط في شاشة المساعد.

يبني GitHub Actions حزمة اختبار موقَّعة ويتحقق من سلامتها وتوقيعها، ثم يرفقها باسم `majlis-debug-apk`. يُحدَّث تنزيل الموقع بعد بناء `main` وإعادة نشر الموقع. نسخ الفروع مخصّصة للاختبار وتتصل بصفحة `/voice.html` على موقع الإنتاج، لذلك تحتاج نشر تغييرات الويب قبل اختبارها من التطبيق. حِزم الاختبار قد تُوقَّع بمفاتيح مختلفة؛ التوزيع المستقر والترقيات دون حذف يتطلبان مفتاح إصدار ثابتًا.

```bash
cd android && gradle :app:assembleDebug    # بناء يدوي (JDK 17 + Android SDK)
```
