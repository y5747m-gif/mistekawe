## موقع رحيق RAHEEQ — الصفحة الرئيسية للمشروع

**`index.html` هو أساس الموقع**: منصة عربية RTL كاملة لتسجيل ولي الأمر،
مبنية كموقع حقيقي بملفات منفصلة (وليس ملف HTML واحدًا):

```text
index.html              الصفحة الرئيسية (كل الأقسام)
css/raheeq.css          الهوية البصرية + الحركات + الاستجابة + منظومة الخطوط متعددة العائلات
css/intro.css           انيميشن البداية: أعمدة بيانية 3D + تجمّع شعار رحيق + الوميض
js/intro.js             مشغّل الانيميشن (غبار ذهبي، خط الترند، التخطي بـ Escape/زر)
js/sounds.js            محرك الأصوات (Web Audio + ملفات MP3) والاهتزاز
js/confetti.js          قصاصات النجاح ماروني + ذهبي
js/validation.js        قواعد التحقق من الحقول
js/uploads.js           قراءة الصور الفعلية وضغطها وحفظها + سجلات المستندات
js/api.js               إرسال الطلب والمستندات إلى خادم الرفع (/api/registrations)
js/app.js               الخطوات، الدخول، النجاح، LocalStorage، المزامنة
server/serve.py         خادم الموقع + واجهة الرفع (Python قياسي فقط)
server/api.py           التحقق والتخزين الآمن للطلبات والمستندات
sounds/*.mp3            الأصوات الثمانية (MP3 حقيقية)
assets/brand/*          الشعار والأيقونات
assets/fonts/*          خط Cairo محلي (احتياطي لـ Google Fonts)
raheeq.webmanifest      إعدادات التطبيق على الجوال
```

```bash
python3 server/serve.py --no-browser      # ثم افتح http://localhost:8000/
```

* `raheeq.html` صار **صفحة تحويل** إلى الجذر، وصفحة «مجلس الصوت» القديمة محفوظة
  في `majlis.html` (روابطها الداخلية محدّثة)، فلا ينكسر أي رابط قديم.
* **هيدر ثابت** باللوجو يمينًا وزر «تسجيل دخول ولي الأمر» يسارًا مع زر الصوت 🔊/🔇.
* **هيرو**: العنوان + وصف + 4 شارات + بطاقة التسجيل على اليسار.
* **3 خطوات مع مؤشر تقدم**: ولي الأمر ← الطالب ← المستندات، مع **رفع الصور الفعلية**:
  كل ملف يُقرأ بـ `FileReader` ثم تُضغط الصورة على `Canvas` (حتى 1400px، JPEG) وتُحفظ
  **بيانات الصورة نفسها** مع سجل الطلب في `raheeq_users`، لا اسم الملف فقط.
  شهادة الميلاد/الصورة الشخصية/بطاقة ولي الأمر إلزامية، وبيان النجاح اختياري.
  صور JPG/PNG/WEBP/GIF/BMP وملفات PDF فقط (حتى 700KB لـ PDF)؛ SVG وHTML مرفوضة.
  بعد الإرسال تظهر الصور في شاشة النجاح، وبعد تسجيل الدخول تظهر في «المستندات المرفوعة»
  مع أزرار **عرض بالحجم الكامل** (نافذة معاينة) و**تنزيل**.
* **تحقق**: الرقم القومي 14 رقمًا، الموبايل 11 رقمًا، الإيميل يحتوي `@`،
  كلمة السر 6 أحرف ومتطابقة، الموافقة على الشروط — رسالة حمراء + اهتزاز خفيف عند الخطأ.
* **شاشة نجاح**: 🎓 تم استلام طلبك بنجاح + اسم ولي الأمر والطالب والصف +
  رقم الطلب `RHQ-1234` + «هنتواصل معاك خلال 24-48 ساعة» + قصاصات ماروني وذهبي.
* **صندوق دخول** و**4 بطاقات قيم** (ثقة، نمو، رعاية، تميز) وفوتر
  `© 2026 رحيق RAHEEQ - info@raheeq.edu`.
* **الحساب والمستندات يُحفظان في `LocalStorage`** (`raheeq_users`) ليتمكن ولي الأمر من
  الدخول لاحقًا من نفس الجهاز ورؤية صوره بعد إغلاق الصفحة. بعد الحفظ يفتح ولي الأمر
  واتساب أكاديمية رحيق (`201151947735`) برسالة جاهزة بكل بيانات الطلب، ويرفق صور المستندات
  من داخل المحادثة (أو عبر زر المشاركة على المتصفحات الداعمة). التخزين محدود (~5MB)؛
  عند امتلائه يقلّل الموقع جودة الصور تلقائيًا، وإن لم يكفِ يطلب صورة أصغر.
  ولي الأمر مسؤول عن سرية كلمة السر الخاصة بحسابه.
* **الأصوات**: الملفات الثمانية من `sounds/` تُحمّل مسبقًا عند فتح الصفحة،
  وتُشغّل عند التفاعل فقط (متوافقة مع الجوال). راجع `sounds/README.md`.

## واجهة الرفع (API)

بعد حفظ الطلب، المسار الأساسي هو **إرسال الطلب إلى واتساب أكاديمية رحيق** بضغطة واحدة
(رسالة جاهزة + إرفاق الصور). وإذا كان خادم الأكاديمية مُشغَّلًا، ترسل الواجهة الطلب إليه
تلقائيًا أيضًا عبر `js/api.js` (مع إعادة محاولة يدوية إن فشل الاتصال)، وتحتفظ بنسخة دائمًا.

```bash
# تشغيل الموقع + الواجهة على نفس المنفذ
python3 server/serve.py --no-browser

# لتفعيل قراءة الطلبات والمستندات (إدارة الأكاديمية)
RAHEEQ_ADMIN_TOKEN="رمز-قوي-خاص" python3 server/serve.py --no-browser

# مجلد تخزين مختلف (افتراضي: data/)
RAHEEQ_DATA_DIR=/var/lib/raheeq python3 server/serve.py
```

| المسار | الوصف | المصادقة |
| --- | --- | --- |
| `GET /api/health` | حالة الواجهة وقدراتها (بلا بيانات شخصية) | عام |
| `POST /api/registrations` | رفع طلب تسجيل مع صور المستندات (JSON + base64) | عام (بحدّ معدل) |
| `GET /api/registrations` | قائمة الطلبات | `X-Admin-Token` |
| `GET /api/registrations/<رقم>` | تفاصيل طلب (بدون كلمة السر) | `X-Admin-Token` |
| `GET /api/registrations/<رقم>/<مستند>` | ملف المستند نفسه | `X-Admin-Token` |

مثال رفع (نفس ما ترسله الواجهة):

```bash
curl -s http://localhost:8000/api/registrations \
  -H 'Content-Type: application/json' \
  -d '{
    "parentName": "محمد أحمد علي حسن",
    "nationalId": "12345678901234",
    "mobile": "01000000000",
    "email": "waly@raheeq.edu",
    "password": "secret1",
    "studentName": "عمر محمد أحمد علي",
    "dob": "2015-05-10",
    "grade": "KG1",
    "address": "القاهرة مدينة نصر",
    "docs": {
      "birthCert": {"name": "birth.jpg", "dataUrl": "data:image/jpeg;base64,..."},
      "photo": {"name": "photo.jpg", "dataUrl": "data:image/jpeg;base64,..."},
      "parentCard": {"name": "card.jpg", "dataUrl": "data:image/jpeg;base64,..."}
    }
  }'

# إعادة قراءة المستندات لاحقًا (إدارة)
curl -s -H 'X-Admin-Token: رمز-قوي-خاص' http://localhost:8000/api/registrations
curl -s -H 'X-Admin-Token: رمز-قوي-خاص' \
  http://localhost:8000/api/registrations/RHQ-1234/photo --output photo.jpg
```

**التخزين والأمان:**

```text
data/                                 (مستثنى من Git — بيانات شخصية)
├── registrations/<رقم الطلب>.json    بيانات الطلب + أوصاف المستندات (بلا base64)
├── registrations/index.json          فهرس مختصر للطلبات
└── uploads/<رقم الطلب>/<المستند>.*   صور المستندات الفعلية (صلاحيات 600)
```

* الصور تُفحص بالبصمة الحقيقية للبايتات (Magic Bytes) لا بالامتداد: JPG/PNG/WEBP/GIF/PDF فقط،
  وSVG/HTML مرفوضة، بحد 4MB للمستند و7MB للطلب.
* كلمة السر تُخزَّن مشفّرة `PBKDF2-SHA256` (120 ألف دورة + ملح عشوائي)، ولا تُعاد أبدًا في أي رد.
* مجلد `data/` و`/server/` و`/.git/` غير قابلة للوصول عبر الموقع، وقراءة الطلبات تتطلب رمز إدارة.
* حدّ معدل 10 طلبات رفع في الدقيقة لكل عنوان IP، وأحجام الطلبات محدودة قبل قراءتها.
* عند إيقاف الخادم أو تعطّله يظل التسجيل يعمل بحفظ محلي كامل (بدون فقدان الصور).

الاختبارات: `node tests/node/raheeq-tests.mjs` (بنية الموقع + المنطق + تدفق رفع الصور وحفظها في `LocalStorage` واستعراضها + الواجهة)،
`python3 tests/python/test_api.py` (26 اختبارًا للخادم: التحقق، البصمة، التخزين، الصلاحيات، حد المعدل)،
`node tests/node/dom-smoke.mjs` (واجهة الاستوديو، يحتاج `jsdom`).

### انيميشن البداية (Intro) — `index.html` فقط

كل مرة تُفتح فيها الصفحة الرئيسية يعمل مشهد افتتاحي سينمائي (~4.6 ثانية)،
ويمكن تخطيه بزر «تخطي» أو بمفتاح `Escape`:

1. **مسرح برغندي**: أرضية بشبكة منظورية ذهبية تتلاشى وشعاع علوي و«غبار» ذهبي عائم.
2. **درجات بيانية 3D**: سبعة أعمدة ثلاثية الأبعاد (وجه أمامي مموّج + وجه علوي ذهبي مضاء + وجه جانبي) تتصاعد كالمدرجات من الطرفين نحو **قمة واحدة في المنتصف**، مع **خط ترند ذهبي** يلمع ويربط قمم الأعمدة (يُقاس ويضبط عبر JS في `js/intro.js`).
3. **الشعار يتفكك ويتجمع**: الشعار الرسمي (`raheeq-mark-vector-white.svg`) يصل إلى **13 شظية** مقصوصة بـ `clip-path` تنطلق من عمق الفراغ (translate3d + rotate3d + blur) وتلتحم واحدة واحدة في منتصف الشاشة **فوق أعلى درجة بيانية**.
4. **الظهور دفعة واحدة**: لحظة التحام آخر شظية ينفجر **وميض** شعاعي + موجة ذهبية دائرية + اشتعال القمة، ثم تظهر قفلة «رحيق» (أميري بتدرج ذهبي) فوق «RAHEEQ» (Cinzel بتباعد حروف)، فالفاصل الذهبي ✦ والسطر «أكاديمية رحيق · بوابة ولي الأمر» (ريم كوفي).
5. شريط تقدّم ذهبي سفلي، وبعدها يزول الغطاء من الـ DOM وتظهر الصفحة.

ملاحظات تنفيذية:

* **CSS 3D خالص + SVG + JS قياسي** — بلا أي مكتبات خارجية (3D حقيقي عبر `perspective`/`transform-style:preserve-3d`).
* أثناء العرض يُقفل التمرير (`body.raheeq-intro-lock`)، وبعده تُزال القفلة ويُزال الغطاء من الـ DOM.
* **`prefers-reduced-motion`** يحترم: يُلغي المشهد ويظهر الشعار فورًا. لو تعذّر الـ JS تمامًا، يُخفي الغطاء نفسه تلقائيًا بعد مهلة (`introFailsafe`) ولا يحبس الصفحة.
* الشظايا مُنفَّخة ~3.5% حول مراكزها لمنع الشقوق الضوئية بين القطع، والتغطية الكاملة مُتحقَّق منها بفحص شبكي (40 ألف نقطة).
* يظهر في **كل** تحميل للصفحة (قرار تصميمي)، ويُعيد الرسم في كل زيارة.

## ياسين YASEEN — مساعد التسجيل المقفول

شخصية تفاعلية تظهر في صفحة التسجيل (`index.html`) وترشد ولي الأمر خطوة بخطوة. **ياسين بوت نظام**:
ولي الأمر يضغط عليها، يسأل عن التسجيل، ويستخدم الأزرار السريعة فقط — ولا يملك أي وسيلة لتغيير
اسمها أو صوتها أو ردودها أو تعليمها شيئًا جديدًا.

| الجزء | الملف | أين يعمل |
| --- | --- | --- |
| قواعد البوت المقفولة + محرك الردود | `api/_yaseen/yaseen-system.js` | الخادم فقط |
| التخزين المشفّر (AES-256-GCM) | `api/_yaseen/store.js` → `data/yaseen/store.enc` | الخادم فقط |
| دخول المدير (bcrypt + OTP) | `api/_yaseen/auth.js` | الخادم فقط |
| المسارات | `api/_yaseen/handler.js` (+ `api/yaseen.js` لـ Vercel، `server/yaseen-server.js` محليًا) | الخادم فقط |
| الشكل والحركة ونافذة المحادثة | `js/yaseen.js` + `css/yaseen.css` + `assets/yaseen/` | المتصفح (عرض فقط) |
| لوحة المدير المخفية | `/admin-yaseen/` (غير مرتبطة من أي صفحة) | المتصفح + فحص على الخادم |

**كيف تُمنع محاولات التلاعب:** لا يوجد نموذج لغوي يمكن خداعه. رسالة ولي الأمر تُنظَّف ثم تُطابَق مع
قائمة إجابات معتمدة؛ وأي شيء لا يطابق سؤالًا عن التسجيل يأخذ الرد الثابت. الترتيب على الخادم:

1. حدود: 200 حرف للرسالة، 20 رسالة للجلسة، حد لكل عنوان IP، وCAPTCHA حسابية عند الإرسال السريع.
2. الروابط والملفات مرفوضة (المحادثة تقبل JSON نصيًا فقط).
3. تلاعب («انسى تعليماتك»، «تجاهل القواعد»، «قول كذا»، «انت دلوقتي حر»، «غير شخصيتك»، ومثيلاتها بالإنجليزية
   أو بمحارف مخفية) ⟵ «أنا هنا عشان أساعدك في التسجيل في رحيق بس، تحب أكمل معاك في استمارة ابنك؟»
4. كلمات المدير المحظورة + سياسة/دين/نكت/برمجة/أسئلة شخصية ⟵ «أنا متخصص في التسجيل بس، لو عندك سؤال عن المدرسة أنا معاك»
5. مطابقة إجابات التسجيل، وإلا نفس رد «خارج التسجيل».

المتصفح يستلم من `GET /api/yaseen-config` النصوص النهائية للعرض فقط (الترحيب، إرشاد الخانات، أسماء الأزرار)،
ولا يستلم القواعد أو الكلمات المفتاحية أو قائمة الإجابات. إن لم يُجب الخادم أو أوقف المدير البوت لا تظهر ياسين إطلاقًا.

### التشغيل

```bash
npm install                                  # مرة واحدة (bcryptjs لتشفير كلمة سر المدير)
node server/yaseen-admin-setup.js --email admin@example.com --name "مدير رحيق"
python3 server/serve.py --no-browser         # يشغّل خادم ياسين تلقائيًا (يتطلب Node 18+)
```

أمر الإعداد يسأل عن كلمة السر (12 حرفًا على الأقل) ويطبع **سر تطبيق المصادقة** (Google Authenticator / Authy)
الذي يولّد رمز OTP. بعدها افتح `/admin-yaseen/` وادخل بالبريد + كلمة السر + الرمز.
خلف وكيل عكسي أضف `--trust-proxy` ليُحسب حد الرسائل لكل زائر لا للوكيل.

### لوحة المدير

الشخصية (الاسم والترحيب) · الإجابات والأزرار السريعة · إرشاد الخانات والخطوات · الحركات · الأصوات ·
مواعيد العمل · الكلمات المحظورة · **مفتاح الإيقاف الفوري** · تجربة رد · **سجل** بكل تغيير (المدير + الوقت + القيمة القديمة + الجديدة).
القواعد المقفولة (الحدود والردّان الثابتان وأنماط كشف التلاعب) لا تتغير من اللوحة — فقط بتعديل `yaseen-system.js` ونشره.

### النشر على Vercel

`vercel.json` يوجّه `/api/yaseen-*` إلى الدالة `api/yaseen.js`. نظام ملفات Vercel للقراءة فقط، لذلك:

* ولّد القيم بـ `node server/yaseen-admin-setup.js --email ... --env` وأضفها في Environment Variables:
  `YASEEN_SECRET`، `YASEEN_ADMIN_EMAIL`، `YASEEN_ADMIN_NAME`، `YASEEN_ADMIN_PASSWORD_HASH`، `YASEEN_ADMIN_TOTP_SECRET`.
* اربط قاعدة **Upstash Redis / Vercel KV** بالمشروع (`KV_REST_API_URL` و`KV_REST_API_TOKEN`) ليُحفظ ما يعدّله المدير
  وتعمل حدود الرسائل عبر كل النسخ. بدونها تعمل ياسين بالإعدادات الافتراضية، واللوحة للقراءة فقط،
  والإيقاف يكون بالمتغير `YASEEN_ENABLED=0`.

> مسار Vercel/KV مكتوب ومغطى باختبارات الوحدة لكنه لم يُجرَّب على نشر حقيقي بعد — جرّبه على Preview أولًا.

### حدود معروفة

* إخفاء «Inspect» في المتصفح غير ممكن فعليًا؛ الحماية الحقيقية أن القواعد والإعدادات ليست في المتصفح أصلًا.
  (قائمة الزر الأيمن معطّلة على الشخصية فقط كإجراء شكلي.)
* الـ CAPTCHA حسابية بسيطة؛ لحماية أقوى ضد البرامج الآلية اربط Cloudflare Turnstile أو hCaptcha.
* الصور السبع للتعابير مولَّدة من الصورة الأصلية (`assets/yaseen/src/`، وتُقصّ بـ `make_sprites.py`).

الاختبارات: `node tests/node/yaseen-tests.mjs` (183 فحصًا).

## مجلس الصوت — واجهة بسيطة + تطبيق APK للهاتف

مجلس الصوت يشغّل الصوت على **عدة سماعات في الوقت نفسه**. صار الآن سهلًا:
واجهة من ثلاث خطوات في المتصفح، وتطبيق **APK أصلي** للهاتف يفعلها فعلًا.

### تحميل التطبيق على الهاتف (APK)

1. افتح رابط التحميل من الهاتف:
   **https://github.com/y5747m-gif/mistekawe/releases/latest**
2. نزّل الملف `majlis-debug.apk` وثبّته (اسمح بـ «تثبيت من مصادر غير معروفة» عند الطلب).
3. افتح التطبيق واتبع الخطوات الثلاث الظاهرة على الشاشة.

> **لماذا APK وليس رابط ويب؟**
> المتصفح على الهاتف (وحتى تطبيق ويب داخل APK) لا يملك صلاحية إرسال الصوت
> إلى أكثر من سماعة بلوتوث؛ تبقى السماعة الثانية صامتة. التطبيق الأصلي يفتح
> **مسار صوت مستقل (AudioTrack) لكل سماعة** ويوجّهه بـ `setPreferredDevice`،
> فتعمل كل السماعات المفعّلة معًا، ويستمر التشغيل والشاشة مطفأة.

كود التطبيق في مجلد `android/`، ويُبنى تلقائيًا إلى APK عبر GitHub Actions
عند أي تعديل (`.github/workflows/build-apk.yml`).

```bash
cd android && gradle :app:assembleDebug    # بناء يدوي (JDK 17 + Android SDK)
```

### الواجهة البسيطة في المتصفح

```bash
python3 server/serve.py      # http://localhost:8000/
```

* `majlis.html` — الواجهة البسيطة: **أضف مخرجًا ← فعّله ← اضغط تشغيل**.
* `hall.html` — الوضع المتقدم (الوكلاء الثمانية، المعايرة، الانحراف).

خطوات التشغيل على الحاسوب:

1. اربط السماعات من إعدادات النظام كالمعتاد.
2. اضغط **إضافة سماعة / مخرج صوت** واختر كل سماعة مرة واحدة
   (أو **إضافة الباقي تلقائيًا** بعد أول اختيار).
3. اضغط **تشغيل**.

* **بلا فجوة:** المقطع التالي يُجدول على خيط الصوت قبل النهاية، وتجمّد
  التبويب يُرجع الساعة بدل إعادة التشغيل.
* **لا يُرسل صوت ولا اسم جهاز إلى أي خادم.** الحساب كله على جهازك.
* الاختبارات: `node tests/node/sound-tests.mjs`

المتجر التراثي في `heritage.html` و`shop.html`. استوديو 3D في `studio.html`.
